## Overview

The Meeting Intelligence Dashboard has 10 page routes and 9 API routes. This document covers every user-facing feature, page by page, including what it does, how it works under the hood, and which data powers it.

### Page Route Map

| Route | Page | Primary Data Source |
|-------|------|-------------------|
| `/` | Team Scorecard | `meetings_list` |
| `/meetings` | Meeting Feed | `meetings_list` |
| `/meetings/[id]` | Meeting Detail | `scored_meetings` |
| `/meetings/[id]/print` | Print / Export View | `scored_meetings` |
| `/companies` | Companies Index | `meetings_list` (aggregated) |
| `/companies/[name]` | Company Detail | `meetings_list` + Company Intelligence API |
| `/reps/[name]` | Rep Profile | `meetings_list` (filtered by rep) |
| `/search` | Ask Blarney (RAG Chat) | `meeting_chunks` + `meetings_list` + `scored_meetings` |
| `/health` | System Health | `scored_meetings` + `scoring_run_log` + `meeting_chunks` + `zoom_users` |
| `/login` | Login | Supabase Auth |

## 1. Team Scorecard (`/`)

The homepage. A single-page executive dashboard that provides a complete picture of meeting performance across the team. Designed for the CRO and CEO to open first thing in the morning and know exactly where things stand.

**Data source:** `meetings_list` (all rows, fetched once via `useMeetingsList()`)

### 1.1 KPI Summary Cards

Four cards in a responsive grid (1 column mobile, 2 tablet, 4 desktop):

| Card | Value | Details |
|------|-------|---------|
| **Total Meetings** | Integer count | Links to `/meetings`. Shows total scored meetings in the system. |
| **Avg Score** | X.X / 10 | Includes a week-over-week delta badge (green up arrow or red down arrow with +/- value). Calculated by comparing this week's average vs. last week's. Uses `date-fns` `parseISO` and `subDays` for proper date comparison. |
| **Avg Health** | X.X / 10 | Averages `client_health_score` across all meetings that have a health value. Only external meetings (discovery, follow-up, onboarding) have health scores. |
| **At-Risk Accounts** | Count | Clickable. Shows distinct companies where `client_health_score < 5`. On click, navigates to the companies page filtered to show only at-risk accounts. |

All cards have hover effects (subtle shadow + lift animation).

### 1.2 Cross-Call Insights

An auto-generated panel of 3-6 insight cards computed from meeting data patterns. Each insight has a typed icon (TrendingUp, TrendingDown, AlertTriangle, BarChart3) and is color-coded:

- **Positive insights** (emerald border/background): trends improving, top performers
- **Negative insights** (red border/background): declining scores, at-risk accounts
- **Neutral insights** (muted border): informational metrics, distribution stats

Insights are generated by the `generateInsights()` function that analyzes:
- Week-over-week score trends per rep
- Companies with declining health scores
- Stage distribution anomalies
- Score outliers (exceptionally high or low)
- Meeting volume changes

Displayed in a responsive grid (1-3 columns depending on screen size).

### 1.3 Rep Comparison Table

A data table comparing all reps side by side. One row per rep, columns:

| Column | Content |
|--------|---------|
| **Rep Name** | Links to `/reps/[name]` |
| **Trend** | Inline sparkline chart (60x24px) built with Recharts `AreaChart`. Green gradient if trending up, red if trending down. Shows weekly average scores. Requires at least 2 data points — shows a dash otherwise. |
| **Meetings** | Total meeting count |
| **Avg Score** | Score badge component (color-coded: emerald >= 8, yellow >= 6, red < 6) |
| **Avg Health** | Formatted score with same color banding |
| **Best Call** | Meeting topic + score, linked to the meeting detail page |
| **Worst Call** | Meeting topic + score, linked to the meeting detail page |

Weekly trends are computed using `date-fns` `startOfWeek` with Monday as week start.

### 1.4 Performance Section

Two side-by-side charts:

**Score Trend Chart (Weekly)**
- Recharts `AreaChart` showing average score per week
- X-axis: week labels (MM/dd format)
- Y-axis: score (0-10 scale)
- Gradient fill under the line (brand blue: `#146DFA`)
- `BrandTooltip` component for hover details
- `ChartDownload` button for PNG export

**Stage Distribution (Donut)**
- Recharts `PieChart` showing meeting count by stage type
- Color-coded: Discovery (blue `#146DFA`), Follow-Up (purple `#8b5cf6`), Onboarding (green `#10b981`), Internal (gray `#94a3b8`)
- Center label showing total count
- `ChartDownload` button for PNG export

### 1.5 Score Distribution by Rep

A stacked bar chart (`BarChart`) showing each rep's meetings broken down by score band:

| Band | Range | Color |
|------|-------|-------|
| Strong | 8.0 - 10.0 | Emerald |
| Average | 6.0 - 7.9 | Yellow |
| Needs Work | 0.0 - 5.9 | Red |

Bars are clickable — clicking a segment opens the meeting feed filtered to that rep and score range.

### 1.6 Competitor Mentions

Tracks mentions of 20+ vendors across client-facing meetings (internal meetings excluded). Vendor list is maintained in `src/lib/constants.ts` (`TRACKED_VENDORS`):

Gong, Chorus, Salesloft, Outreach, Apollo, 6Sense, ZoomInfo, Clari, Salesforce, Pardot, Marketo, Drift, Intercom, Definitive Healthcare, Conversica, Lemlist, Lavender, Regie, Orum, HubSpot, Clay, HeyReach, Instantly.

Scans `meeting_summary` text for mentions. Displays as a ranked list with mention count and most recent mention date.

### 1.7 Recent Activity

A timeline of the 5-10 most recent meetings, displayed as compact cards with topic, rep, score badge, and relative time ("2 hours ago", "yesterday").

## 2. Meeting Feed (`/meetings`)

A filterable, sortable list of all scored meetings. The primary navigation page for finding specific meetings.

**Data source:** `meetings_list` (fetched with filter parameters via `useMeetingsList()`)

### 2.1 Filter Section

Wrapped in a bordered card with a "Filters" header and the `SlidersHorizontal` icon. All filters are optional and combinable.

| Filter | Type | Options |
|--------|------|---------|
| **Rep** | Select dropdown | All reps from `zoom_users` (enabled) |
| **Stage** | Select dropdown | Discovery, Follow-Up, Onboarding, Internal |
| **Period** | Select dropdown | Last 7 Days, Last 30 Days, Last 90 Days, All Time |
| **From Date** | Date input | Custom start date (native `<input type="date">`) |
| **To Date** | Date input | Custom end date |
| **Sort** | Select dropdown | Newest First, Oldest First, Highest Score, Lowest Score |
| **Company** | Text input | Search icon, filters by company name (case-insensitive substring match via `ilike`) |

**Mutual exclusivity rule:** Period presets and custom From/To dates are mutually exclusive. Selecting a Period preset clears From/To. Setting a custom date resets Period to "All Time". Both paths use `parseISO()` for proper date comparison.

**Clear Filters button:** Appears only when at least one filter is active. Resets all filters to defaults.

### 2.2 Meeting Cards

Each meeting renders as a card (`MeetingCard` component) showing:
- Topic (linked to `/meetings/[id]`)
- Stage type badge (color-coded)
- Rep name (linked to `/reps/[name]`)
- Company name (linked to `/companies/[name]`)
- Date and duration
- Score badge (color-coded)
- Health score (if available)
- Meeting summary (truncated to 2 lines)

Cards are displayed in a responsive list layout.

### 2.3 Empty State

When no meetings match the filters, an `EmptyState` component displays with an illustration and "No meetings found" message, plus a hint about adjusting filters.

### 3.4 Transcript Viewer

A persistent notes system that allows team members to annotate any meeting. Notes are section-level — each tab has its own notes area.

## 7. Ask Blarney (`/search`)

The AI-powered conversational search interface. Uses RAG (Retrieval-Augmented Generation) to answer questions by searching across all 611 transcript chunks and 76 scored meetings.

**Data sources:** `meeting_chunks` (vector search via `match_meeting_chunks` RPC), `meetings_list` (score context), `scored_meetings` (JSONB intelligence for matched meetings)
**AI models:** Claude Sonnet 4 (conversation), Gemini Embedding API (`gemini-embedding-001`, query embedding)

### 7.1 Empty State / Suggested Prompts

When no conversation exists, the page shows 6 suggested prompts:

1. "Compare all reps' average meeting scores"
2. "What action items came from last week's internal meetings?"
3. "Which accounts need attention based on recent health scores?"
4. "What competitors were mentioned in recent calls?"
5. "Show coaching insights for Tyler across all meetings"
6. "What's the breakdown of meeting stages across all reps?"

Clicking a prompt immediately sends it as a query.

### 7.2 Streaming Chat

- Real-time token-by-token streaming via Anthropic's `toReadableStream()` API
- Messages render incrementally as tokens arrive
- The chat area auto-scrolls to the bottom during streaming
- Streaming indicator shows while the response is being generated

### 7.3 Charts

The AI generates interactive charts when the question involves data comparison. Three chart types:

| Type | When Used | Example Query |
|------|----------|--------------|
| **Bar** | Comparing values across categories | "Compare reps' average scores" |
| **Donut** | Showing proportions / distribution | "Show meeting type breakdown" |
| **Line** | Showing trends over time | "How have scores changed over the past month?" |

Charts are rendered from a special ` ```chart ` code block in the AI response:

```
chart
{"type":"bar","title":"Rep Comparison","data":[{"label":"Tyler","value":7.2},{"label":"Jake","value":6.8}]}
```

Each chart includes a `ChartDownload` button for PNG export.

### 7.4 Source Citations

The AI includes a ` ```sources ` block listing meetings it referenced. Each source is rendered as a clickable card showing:
- Meeting topic
- Rep name
- Date
- Company
- Score badge

Clicking a source navigates to `/meetings/[id]` for that meeting.

### 7.5 Follow-Up Suggestions

After each response, the AI suggests 2-3 follow-up questions in a ` ```followups ` block. These render as clickable chips below the response. Clicking a chip sends it as the next query.

Suggestions are contextual — if the AI mentioned a specific rep, it might suggest "What coaching insights exist for [rep]?". If it mentioned a risk, it might suggest "Show the health trend for [company]."

### 7.6 Thumbs Up / Thumbs Down Feedback

Each assistant message has feedback buttons:
- **Thumbs up:** Logs a `thumbs_up` event to `chat_analytics`
- **Thumbs down:** Logs a `thumbs_down` event to `chat_analytics`

Feedback is anonymous (tied to session, not displayed to other users).

### 7.7 Conversation Persistence

- Conversations are saved to `localStorage` (`meeting-intel-chat` key)
- Session IDs are stored in `sessionStorage` (`meeting-intel-session` key)
- Refreshing the page restores the conversation
- Messages are saved whenever streaming completes (not during)

### 7.8 Clear Chat

A "Clear" button (with `Trash2` icon) in the input area. Shows a `window.confirm()` dialog: "Clear this conversation?". On confirm:
1. Logs a `clear` event to `chat_analytics`
2. Clears all messages from state and localStorage
3. Generates a new session ID
4. Returns to the empty state with suggested prompts

### 7.9 Soft Turn Nudge

At 15+ conversation turns, the UI shows a gentle suggestion to clear the conversation for better results. This is a UX consideration — very long conversations can degrade response quality as the context window fills up.

### 7.10 Rate Limiting

Two-tier rate limiting (see Database Schema doc, Table 6):
- **Daily limit:** 50 queries per user (resets at midnight UTC)
- **Burst limit:** 10 queries per 5-minute window

When limits are hit, the API returns a 429 with a user-friendly error message. The chat interface displays this as a system message.

### 7.11 How RAG Works (Query Flow)

1. User types a question
2. Chat API receives the message + conversation history (last 16 turns)
3. Query is embedded using Gemini Embedding API (3072 dimensions)
4. In parallel:
   - `match_meeting_chunks` RPC runs vector search (cosine similarity, filtered at > 0.3 threshold)
   - All rows from `meetings_list` are fetched for score context
5. For matched chunks, the corresponding `scored_meetings` rows are fetched to get JSONB intelligence (rep_score, meeting_score, icp_score, engagement_score, delivery_score, internal_summary)
6. All context is assembled into a prompt:
   - Meeting score data (all meetings with ID, rep, topic, stage, scores, dates)
   - Coaching and intelligence blocks (from matched meetings' JSONB)
   - Transcript excerpts (from matched chunks)
   - The user's question
7. Claude Sonnet 4 generates a streaming response with the RAG system prompt
8. Response streams back token by token via SSE
9. Query is logged to `chat_analytics` (fire-and-forget, never blocks response)

Dynamic chunk count: broad queries ("compare all reps") retrieve 15 chunks, long queries (30+ words) retrieve 12, standard queries retrieve 8.

## 8. System Health (`/health`)

An operational monitoring page for the pipeline and system status. Designed for GTM engineers to quickly verify everything is working.

**Data sources:** `scored_meetings` (status counts, sync timestamps), `scoring_run_log` (pipeline history), `meeting_chunks` (chunk count), `zoom_users` (rep count)

### 8.1 Pipeline Sync Status

Three data points:
- **Last Sync:** Relative time since the most recent `scored_at` timestamp (e.g., "3 hours ago")
- **Next Estimate:** Calculated as `last_sync + 8 hours` (configurable via `NEXT_PUBLIC_PIPELINE_INTERVAL_HOURS` env var)
- **Pending:** Count of meetings with `status = 'captured'` and `scored_at IS NULL` (captured but not yet scored)

Status indicator: **Fresh** (green, < 8 hours), **Stale** (yellow, 8-24 hours), **Critical** (red, > 24 hours), **Unknown** (gray, no data).

Auto-refreshes every 5 minutes (`refetchInterval: 5 * 60 * 1000`).

### 8.2 Service Status (Connection Status)

Checks connectivity to external services:

| Service | Check Method |
|---------|-------------|
| **Supabase** | Runs a simple query against `scored_meetings` |
| **Scoring Pipeline** | Checks if most recent `scoring_run_log` entry has `status = 'completed'` |
| **RAG Search** | Checks if `meeting_chunks` has rows with non-null `chunk_embedding` |

Each shows a status indicator: green (connected), yellow (degraded), red (down).

### 8.3 System Metrics

Key numbers displayed as metric cards:

| Metric | Source |
|--------|--------|
| Total Meetings | Count of `scored_meetings` rows |
| Embedded Meetings | Count where `embedded_at IS NOT NULL` |
| Total Chunks | Count of `meeting_chunks` rows |
| Enabled Reps | Count of `zoom_users` where `enabled_for_scoring = true` |

### 8.4 Status Breakdown Donut

A Recharts `PieChart` showing the distribution of meeting statuses:
- **Scored** (green): `status = 'scored'`
- **Captured** (yellow): `status = 'captured'` (pending scoring)
- **Error** (red): `status = 'error'`

Includes `ChartDownload` for PNG export.

### 8.5 Processing Log

A table of recent pipeline runs from `scoring_run_log`, sorted by `run_started_at` descending. Columns:

| Column | Content |
|--------|---------|
| Workflow | Workflow name |
| Started | Formatted timestamp |
| Completed | Formatted timestamp (or "Running..." if null) |
| Captured | `meetings_captured` count |
| Scored | `meetings_scored` count |

| No Contact | `meetings_no_contact` count |

## 11. Cross-Cutting Features

Features that span multiple pages.

### 11.1 Notifications Bell

Located in the app header (top bar). Shows a bell icon with an unread count badge (red circle, max "9+").

**Alert types:**

| Type | Icon | Trigger |
|------|------|---------|
| `at_risk` | AlertTriangle | Company with `client_health_score < 5` |
| `coaching` | TrendingDown | Rep with `overall_score < 6` on recent meeting |
| `pipeline` | Activity | Pipeline sync is stale (> 8 hours) or failed |
| `low_score` | Target | Meeting scored below 5 overall |

**Severity colors:**
- Red: at-risk accounts, pipeline failures
- Yellow: coaching needs, low scores

Clicking the bell opens a dropdown listing all alerts. Opening the dropdown marks all alerts as read.

Each alert links to the relevant page (company, meeting, or health page).

**Data source:** Computed client-side from `meetings_list` + `useSyncStatus()`.

### 11.2 Sync Indicator

A small status indicator in the app header showing the pipeline sync status:
- **Green dot:** Fresh (last sync < 8 hours)
- **Yellow dot:** Stale (8-24 hours)
- **Red dot:** Critical (> 24 hours)

Hover shows a tooltip with the last sync time and next estimated sync.

**Data source:** `useSyncStatus()` hook, which queries `scored_meetings.scored_at` and counts pending meetings.

### 11.3 Dark / Light Mode

A theme toggle in the app header (sun/moon icon). Uses the `ThemeToggle` component.

- Persists preference in `localStorage`
- Respects system preference on first load
- Smooth transition between modes
- All components, charts, and badges adapt to the current theme
- Chart gradients, borders, and text colors all have `dark:` variants

### 11.4 Cmd+K Shortcut

Global keyboard shortcut (Cmd+K on Mac, Ctrl+K on Windows/Linux) that navigates to `/search` (Ask Blarney). Provides quick access to the AI chat from any page.

### 11.5 Chart Download

Available on every chart in the dashboard (all Recharts components). The `ChartDownload` component renders a download icon button.

On click:
1. Captures the chart container as a canvas using `html2canvas`
2. Adds a title and legend overlay
3. Exports as a PNG file
4. Downloads with a descriptive filename

### 11.6 Collapsible Sidebar

The main navigation sidebar (left side):
- **Desktop:** Permanently visible, can be collapsed to icon-only mode
- **Mobile:** Hidden by default, opens as an overlay via the hamburger menu (`MobileNav` component)

Navigation items are grouped:
- **Analysis:** Scorecard, Meetings, Companies
- **Tools:** Ask Blarney, System

The active page is highlighted with a brand blue accent.

### 11.7 Conditional Shell

The `ConditionalShell` component determines whether to render the full app shell (sidebar + header + notifications) or a bare layout. The login page uses the bare layout; all other pages use the full shell.

### 11.8 Error Boundary

A global `error.tsx` component catches unhandled errors and displays a user-friendly error page with a "Try again" button that resets the error state.

### 11.9 Loading States

- **Global:** `loading.tsx` provides a page-level skeleton screen during route transitions
- **Per-component:** Each data-dependent component shows skeleton loaders (`Skeleton` component) while data is fetching via React Query
- **Stale-while-revalidate:** React Query's `staleTime: 5 * 60 * 1000` (5 minutes) means data loads instantly from cache while revalidating in the background
